2)EKS 개요
=>Elastic Kubernetes Service
=>Kubernetes를 제어하는 Control Plain을 제공하는 Managed Service
=>2017년 출시되었고 국내에서는 2019년에 서비스 되기 시작함
=>VPC 와 통합
- Kubernetes Cluster에서는 Pod Network로 Data Network의 Network와는 다른 자체 네트워크 체계를 배치하기 때문에 Cluster 외부에서는 Pod에 명시적으로 End Point(서비스)를 생성하지 않으면 통신이 불가능
- EKS에서는 Amazon VPC 통합 네트워킹을 지원하고 있어서 Pod에서 VPC 내부 주소 대역을 사용할 수 있고 Cluster 외부와의 통신을 간단하게 구현할 수 있음
=> IAM을 통한 인증과 인가
=> ELB 와 연계
- EKS에서 Load Balancer를 설정하면 Load Balancer 서비스인 ELB가 생성되는데 이것 기반으로 해서 HTTPS나 경로 기반 라우팅 등의 기능을 구현
=>Data Plane을 선택
- Kubernetes는 컨트롤 플레인과 데이터 플레인으로 구성되는데 컨트롤 플레인은 EKS에서 Managed Service로 제공
- 초창기에는 EKS 와 별도로 EC2로 데이터 플레인을 만들고 직접 관리해야 했지만 AWS가 발전해 데이터 플레인 관리를 도와주는 기능이 제공됨
- Fargate는 데이터 플레인 관리가 필요없는 만큼 pod가 배포되는 호스트에 사용자 접속도 제한되며 거기에 따른 제약도 있음
- 데이터 플레인 종류
Amazon EC2

3)구축 방법
=>구축 방법
- EKS Cluster 구축 도구인 eksctl을 이용
- AWS 관리 콘솔 또는 AWS CLI를 이용

=>eksctl
- EKS 클러스터 구축 및 관리를 하기 위한 오픈 소스 명령 도구
- 기본 적인 구성은 eksctl create cluster 명령으로 클러스터 구축
- 다양한 옵션을 설정해서 유연하게 구성을 변경할 수 있음
- 오픈소스 프로젝트 이기 때문에 계속 기능이 추가되고 있음
- eksctl을 이용하면 VPC, subnet, 보안 그룹 등 EKS Cluster를 축하는데 필요한 리소스를 한 번에 구성할 수 있음
- EKS Cluster는 정지해도 과금이 되기 때문에 이를 막으려면 Cluster를 삭제 해야 함
- eksctl로 VPC 등을 생성한 경우 EKS Cluster를 삭제할 때 VPC 등 도 함께 삭제되어 버림
 
=>VPC
- AWS에서는 서버 등의 리소스를 VPC 라는 논리적으로 분리된 영역을 이용하여 관리하는데 1개의 AWS 계정에 VPC 여러 개를 생성할 수 있지만 기본적으로 VPC끼리는 독립적인 환경이고 명시적으로 VPC를 연결하지 않는 한 VPC가 통신은 할 수 없음
- VPC는 하나의 Region을 선택
- 대부분의 리소스는 하나의 Region에 배치하고 백업용을 다른 Region에 배치
- Region 안에는 여러 개의 가용 영역(AZ)이 존재하는데 가용 영역 여러 개에 리소스를 배치
- VPC 안에는 다시 Subnet을 이용해서 네트워크를 분할 할 수 있음
- Subnet은 가용 영역 1개만 사용
- 여러 개의 가용 영역을 사용하면 Subnet을 여러 개 생성해야 함
- 인터넷에 접속할 수 있는 public subnet 과 인터넷에 접속할 수 없는 private subnet 두 종류

=>기본 리소스 구축
- CloudFormation 에서 기본 리소스 생성을 위해서 수행
AWSTemplateFormatVersion: '2010-09-09'

Parameters:
  ClusterBaseName:
    Type: String
    Default: eks-work

  TargetRegion:
    Type: String
    Default: ap-northeast-2

  AvailabilityZone1:
    Type: String
    Default: ap-northeast-2a

  AvailabilityZone2:
    Type: String
    Default: ap-northeast-2b

  AvailabilityZone3:
    Type: String
    Default: ap-northeast-2c

  VpcBlock:
    Type: String
    Default: 192.168.0.0/16

  WorkerSubnet1Block:
    Type: String
    Default: 192.168.0.0/24

  WorkerSubnet2Block:
    Type: String
    Default: 192.168.1.0/24

  WorkerSubnet3Block:
    Type: String
    Default: 192.168.2.0/24

Resources:
  EksWorkVPC:
    Type: AWS::EC2::VPC
    Properties:
      CidrBlock: !Ref VpcBlock
      EnableDnsSupport: true
      EnableDnsHostnames: true
      Tags:
        - Key: Name
          Value: !Sub ${ClusterBaseName}-VPC

  WorkerSubnet1:
    Type: AWS::EC2::Subnet
    Properties:
      AvailabilityZone: !Ref AvailabilityZone1
      CidrBlock: !Ref WorkerSubnet1Block
      VpcId: !Ref EksWorkVPC
      MapPublicIpOnLaunch: true
      Tags:
        - Key: Name
          Value: !Sub ${ClusterBaseName}-WorkerSubnet1

  WorkerSubnet2:
    Type: AWS::EC2::Subnet
    Properties:
      AvailabilityZone: !Ref AvailabilityZone2
      CidrBlock: !Ref WorkerSubnet2Block
      VpcId: !Ref EksWorkVPC
      MapPublicIpOnLaunch: true
      Tags:
        - Key: Name
          Value: !Sub ${ClusterBaseName}-WorkerSubnet2

  WorkerSubnet3:
    Type: AWS::EC2::Subnet
    Properties:
      AvailabilityZone: !Ref AvailabilityZone3
      CidrBlock: !Ref WorkerSubnet3Block
      VpcId: !Ref EksWorkVPC
      MapPublicIpOnLaunch: true
      Tags:
        - Key: Name
          Value: !Sub ${ClusterBaseName}-WorkerSubnet3

  InternetGateway:
    Type: AWS::EC2::InternetGateway

  VPCGatewayAttachment:
    Type: AWS::EC2::VPCGatewayAttachment
    Properties:
      InternetGatewayId: !Ref InternetGateway
      VpcId: !Ref EksWorkVPC

  WorkerSubnetRouteTable:
    Type: AWS::EC2::RouteTable
    Properties:
      VpcId: !Ref EksWorkVPC
      Tags:
        - Key: Name
          Value: !Sub ${ClusterBaseName}-WorkerSubnetRouteTable

  WorkerSubnetRoute:
    Type: AWS::EC2::Route
    Properties:
      RouteTableId: !Ref WorkerSubnetRouteTable
      DestinationCidrBlock: 0.0.0.0/0
      GatewayId: !Ref InternetGateway

  WorkerSubnet1RouteTableAssociation:
    Type: AWS::EC2::SubnetRouteTableAssociation
    Properties:
      SubnetId: !Ref WorkerSubnet1
      RouteTableId: !Ref WorkerSubnetRouteTable

  WorkerSubnet2RouteTableAssociation:
    Type: AWS::EC2::SubnetRouteTableAssociation
    Properties:
      SubnetId: !Ref WorkerSubnet2
      RouteTableId: !Ref WorkerSubnetRouteTable

  WorkerSubnet3RouteTableAssociation:
    Type: AWS::EC2::SubnetRouteTableAssociation
    Properties:
      SubnetId: !Ref WorkerSubnet3
      RouteTableId: !Ref WorkerSubnetRouteTable

Outputs:
  VPC:
    Value: !Ref EksWorkVPC

  WorkerSubnets:
    Value: !Join
      - ","
      - [!Ref WorkerSubnet1, !Ref WorkerSubnet2, !Ref WorkerSubnet3]

  RouteTable:
    Value: !Ref WorkerSubnetRouteTable

- 스택 생성을 눌러서 템플릿 파일을 업로드하면 VPC가 생성

5)데이터베이스 설정
=>환경 설정
- Amazon RDS는 AWS가 제공하는 관계형 데이터베이스의 Managed Service로 RDS를 사용하면 AWS 관리 콘솔이나 AWS CLI, CloudFormation 등을 이용해서 데이터베이스를 구축할 수 있을 뿐 아니라 통상적인 데이터베이스 운영에 관련된 작업 부하를 줄일 수 있습니다.
- Amazon RDS에서는 데이터베이스가 설치된 OS에 로그인 할 수 없는 데이터베이스 환경 관련 제약 사항이 존재
- 데이터베이스 관리용 서버로 Bastion Host를 구축하여 사용
Bastion Host는 외부에서 내부 네트워크로 접근할 수 있는 유일한 방법인 접근점
보안성이 높은 인프라와 외부 인터넷을 연결하는 중계 서버로 작동하며 모든 인바운드 트래픽은 Bastion Host를 통과해야 내부 네트워크로 들어갈 수 있음
- Bastion Host는 AWS 가상 서버인 EC2로 구축
