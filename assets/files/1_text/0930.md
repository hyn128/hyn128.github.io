3)Key Value Store Database
=>개요
- Key 와 Value를 쌍으로 저장하는 데이터베이스
- 관계형 데이터베이스에 비해서 유연성이 높아서 형식에 상관없이 데이터를 입력할 수 있고 데이터에 대한 엑세스가 빠름
- 빅데이터 나 IoT 와 같은 대용량 데이터를 빠르게 처리하는 경우에 사용
- AWS에서는 Dynamo DB 와 ElasticCache

=>DynamoDB
- AWS에서 제공하는 Serverless 기반 Key-Value NoSQL Database
- 높은 성능 과 비용적인 측면에서 이점을 가져옴
- VPC가 불필요하므로 Lambda 등과 같은 VPC를 사용하지 않는 애플리케이션 환경에 유리
- ACID 트랜잭션, 데이터 암호화, 접근 제한 등의 서비스를 갖추고 있음
- 테이블을 글로벌 테이블로 만들면 전 세계 각 Region에 분산되어 복제되며 각 Region의 테이블의 데이터가 갱신되면 자동으로 동기화가 가능
- HTTP로 통신
일반적인 데이터베이스는 TCP Connection 기반이라서 Connetion을 만드는 과정이 필요하지만 DynamoDB는 ConnectionLess
일반적인 데이터베이스 프로그래밍은 TCP Connetion 시간을 줄이기 위해서 Connection Pool을 만들어서 사용
- Serverless
Server를 구축하면 기본적으로 서버가 사용이 되지 않더라도 요금이 부과되지만 Serverless는 사용한 만큼만 비용을 지불

=>ElastiCache
- In Memory Database
- 완전 관리형 인 메모리 캐싱 서비스
- 외부 기억 장치에 읽기/쓰기를 수행하지 않고 메모리에 보관하는 방식
- 실제 읽고 쓰는 속도는 DynamoDB 보다 빠르지만 휘발성
- Redis 와 Memcached가 대표적인 인 메모리 데이터베이스
- Redis 와 Memcached 와 호환이 되기 때문에 현재 사용하고 있는 애플리케이션을 변경하지 않아도 사용 가능

import os
import paramiko

#호환성 배치
if not hasattr(paramiko, "DSSKey"):
    paramiko.DSSKey = None

from pymongo import MongoClient
from sshtunnel import SSHTunnelForwarder

#설정 정보 설정

#Bastion HOST 설정(SSH 터널링의 제공할 EC2 정보)
EC2_PUBLIC_IP = "EC2 IP 정보"
EC2_USER = "EC2 계정"
EC2_KEY_PATH = os.path.expanduser("EC2 접속을 위한 pem 파일 경로")

#Document DB 정보 설정
DOCDB_HOST = "클러스터 End Point"
DOCDB_PORT = 27017
DOCDB_USER = "데이터베이스 계정"
DOCDB_PASSWORD = "데이터베이스 비밀번호"
CA_CERT_PATH = "documentdb 접속을 위한 pem 파일 경로"

#터널링 및 DB 연결
def connect_and_query():
    with SSHTunnelForwarder(
        ssh_address_or_host=(EC2_PUBLIC_IP, 22),
        ssh_username=EC2_USER,
        ssh_pkey=EC2_KEY_PATH,
        remote_bind_address=(DOCDB_HOST, DOCDB_PORT)
    ) as tunnel:
        print(f"[+] SSH 터널 연결 성공")
        #MongoDB연결
        client = MongoClient(
            host="127.0.0.1",
            port=tunnel.local_bind_port,
            username=DOCDB_USER,
            password=DOCDB_PASSWORD,
            authSource="admin",
            tls=True,
            tlsAllowInvalidHostnames=True,
            directConnection=True,
            retryWrites=False
        )
        try:
            client.admin.command("ping")
            print("[+] DocumentDB 연결 확인")

            db = client["test_database"]
            collection = db["users"]

            test_doc = {"name":"adam", "role":"engineer", "framework":"FastAPI"}
            insert_result = collection.insert_one(test_doc)
            print(f"[+] 데이터 삽입 완료")

            found_doc = collection.find_one({"name":"adam"})
            print(f"[+] 데이터 조회 결과:{found_doc}")
        except Exception as e:
            print(f"[-] 에러 발생: {e}")
        finally:
            client.close()
            print("[+] DB 클라이언트 종료")

if __name__ == "__main__":
    connect_and_query()

5.AWS Storage System
1)Backup
=>백업의 형태
- 온프레미스 환경의 데이터를 AWS에 백업
- AWS에 구축한 시스템을 백업

=>인프라 핵심 설계 사항
- 스토리지 게이트웨이를 이용한 자동 백업: 온프레미스 환경에 스토리지 게이트웨이를 설치해서 백업용 스토리지를 만들어 S3에 자동 백업
- S3 와 글래이셔로 수명 주기 관리: 로그 파일을 S3의 기능으로 백업하면서 온라인 보관 기간을 넘은 파일을 글래이셔에 아카이브
- 용량이 큰 이미지 파일이나 데이터베이스는 직접 S3에 백업: 스토리지 게이트웨이에 보과되는 종량제 요금을 줄이기 위해서 용량이 큰 데이터는 스크립트를 사용해서 S3에 백업
- 비용을 절감하면서도 운영에 손이 많이 가지 않는 방식으로 백업

=>온프레미스 환경의 데이터 백업
- 오브젝트 스토리지 서비스인 S3를 명령행 인터페이스를 통해 이용하는 패턴
	백업 대상이 파일인 경우 유효하며 간편하면서도 저렴
	S3는 범용적인 파일 저장소 서비스라서 온라인 파일 서버처럼 사용이 가능
	서로 다른 가용 영역에 3중화 되어 있어서 99.99999999% 의 내구성

- 가상 서버인 EC2 와 가상 스토리지인 EBS로 구축한 백업용 서버에 데이터를 동기화시키는 패턴
	첫번째 방법보다 비용이 더 들지만 데이터베이스의 백업을 유연하게 실행할 수 있음
	백업 대상 EC2에서 유틸리티를 실행시키면 DB를 온라인 백업 할 수 있음

- 자동 백업 서비스인 AWS 스토리지 게이트웨이를 이용하는 패턴
	앞의 2가지 방법보다 적은 노력으로 자동 백업 환경을 구축할 수 있으면서도 백업 관리의 일원화도 가능
	스토리지 게이트웨이는 온프레미스 환경에 있는 서버에 스토리지 관리 전용 소프트웨어를 설치하여 AWS와 접속하는 서비스

2)S3
=>개요
- Simple Storage Service의 약자
- 용량 제한없이 파일을 저장할 수 있고 HTTP 프로토콜을 이용해서 파일에 접근할 수 있으며 안정성이 뛰어나고 가용성이 높음
- 대용량 파일 저장에 적합
- 정적 웹 서비스 가능
- S3 자체가 수천 대 이상의 매우 성능이 좋은 웹 서버로 구성되어 있어서 Auto Scaling 이나 Load Balancing에 신경 쓸 필요가 없음
- 동적 웹 사이트 와 정적 웹 사이트가 있는 경우 정적 웹 사이트를 S3에 배포하는 것이 EC2를 이용하는 것보다 성능도 높일 수 있고 비용도 절감
- HTTP 프로토콜을 사용하므로 별도의 클라이언트나 Active X 설치없이 웹 브라우저에서 바로 사용 가능
- 넷플릭스의 컨텐츠와 Airbnb의 사진이나 정적 파일이 S3를 통해서 서비스 되고 있음

=>기본 개념
- Object
파일과 메타 데이터로 구성된 데이터가 저장되는 기본 단위
Key가 객체 이름이 되고 Value가 객체의 데이터가 되는 형태로 저장
객체 하나의 크기는 1Byte ~ 5TB
메타 데이터는 MIME 형식으로 확장자를 통해서 자동 설정되고 사용자가 임의로 지정

- Bucket
S3에서 생성할 수 있는 최상위 디렉토리
리전 별로 생성되며 계정 별로 100개까지 가능
Bucket 안에 객체가 저장되고 안에 디렉토리를 생성할 수 있음(디렉토리는 이름에 포함될 뿐)

- 내구성이 다른 2가지 스토리지 옵션
Standard Storage: 99.99999999%의 내구성을 가짐
Reduced Redundancy Storage: 표준 스토리지 보다는 낮은 99.99%의 내구성을 가지고 있는데 데이터를 복제한 사본의 수를 줄여서 비용을 줄이는 방식으로 원본을 가지고 있으면 복원이 가능한 썸네일 저장에 주로 이용

- 요금: 저장 용량 과 데이터 전송량, HTTP 요청 개수로 책정

import org.springframework.http.HttpStatus;
import org.springframework.http.HttpStatusCode;
import org.springframework.http.ResponseEntity;
import org.springframework.stereotype.Component;
import org.springframework.web.ErrorResponse;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.multipart.MaxUploadSizeExceededException;

@Component
@RestControllerAdvice
public class FileUploadFailedException {
    @ExceptionHandler(MaxUploadSizeExceededException.class)
    protected ResponseEntity<ErrorResponse>
    handleMaxUploadSizeExceededException(MaxUploadSizeExceededException e){
        ErrorResponse response = ErrorResponse.builder(
                e, HttpStatus.BAD_REQUEST, "용량 초과")
                .build();
        return new ResponseEntity<>(response,
                HttpStatus.BAD_REQUEST);
    }
}

- 업로드할 파일의 경로를 만들어주는 클래스
public class CommonUtils {
    private static final String FILE_EXTENSION_SEPARATOR = ".";
    private static final String CATEGORY_PREFIX = "/";
    private static final String TIME_SEPARATOR = "_";

    public static String buildFileName(String category,
                                       String originalFileName){
        int fileExtensionIndex = originalFileName.lastIndexOf(
                FILE_EXTENSION_SEPARATOR);
        String fileExtension = originalFileName.substring(fileExtensionIndex);
        String fileName = originalFileName.substring(0, fileExtensionIndex);
        String now = String.valueOf(System.currentTimeMillis());

        return category + CATEGORY_PREFIX + fileName + TIME_SEPARATOR +
                now + fileExtension;
    }
}

- 서비스 클래스를 생성
import com.amazonaws.auth.AWSCredentials;
import com.amazonaws.auth.AWSStaticCredentialsProvider;
import com.amazonaws.auth.BasicAWSCredentials;
import com.amazonaws.services.s3.AmazonS3;
import com.amazonaws.services.s3.AmazonS3ClientBuilder;
import com.amazonaws.services.s3.model.CannedAccessControlList;
import com.amazonaws.services.s3.model.ObjectMetadata;
import com.amazonaws.services.s3.model.PutObjectRequest;
import jakarta.annotation.PostConstruct;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;
import org.springframework.web.multipart.MultipartFile;

import java.io.IOException;
import java.io.InputStream;

@Slf4j
@RequiredArgsConstructor
@Service
public class AwsS3Service {
    private AmazonS3 amazonS3Client;

    @Value("${cloud.aws.credentials.accessKey}")
    private String accessKey;

    @Value("${cloud.aws.credentials.secretKey}")
    private String secretKey;

    @Value("${cloud.aws.s3.bucket}")
    private String bucketName;

    @Value("${cloud.aws.region.static}")
    private String region;

    @PostConstruct
    public void setS3Client(){
        AWSCredentials credentials = new BasicAWSCredentials(this.accessKey,
                this.secretKey);
        amazonS3Client = AmazonS3ClientBuilder
                .standard()
                .withCredentials(new AWSStaticCredentialsProvider(credentials))
                .withRegion(this.region)
                .build();

    }

    //파일 경로의 적합성 여부 확인해주는 메서드
    private boolean validateFileExists(MultipartFile multipartFile){
        boolean result = true;
        if(multipartFile.isEmpty()){
            result = false;
        }
        return result;
    }

    //업로드 메소드
    public String uploadFileV1(String category, MultipartFile multipartFile){
        boolean result = validateFileExists(multipartFile);
        if(result == false){
            return null;
        }
        String fileName = CommonUtils.buildFileName(category, multipartFile.getOriginalFilename());
        ObjectMetadata objectMetadata = new ObjectMetadata();
        objectMetadata.setContentType(multipartFile.getContentType());
        try(InputStream inputStream = multipartFile.getInputStream()){
            amazonS3Client.putObject(new PutObjectRequest(
                    bucketName, fileName,inputStream,objectMetadata)
                    .withCannedAcl(CannedAccessControlList.PublicRead));

        }catch(IOException e){
            return null;
        }
        return amazonS3Client.getUrl(bucketName, fileName).toString();
    }
}

- Controller 클래스
import lombok.RequiredArgsConstructor;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RequestPart;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.multipart.MultipartFile;

@RestController
@RequiredArgsConstructor
public class S3FileController {
    private final AwsS3Service awsS3Service;

    @PostMapping("/upload")
    public String uploadFile(@RequestParam("category") String category,
                             @RequestPart(value="file")MultipartFile multipartFile){
        return awsS3Service.uploadFileV1(category, multipartFile);
    }
}

- 다운로드는 존재하는 파일의 이름을 알아야 함
일반적으로는 파일의 이름이나 경로를 데이터베이스에 전부 저장하고 다운로드 할 파일의 목록을 클라이언트에 출력하고 링크를 설정해서 다운로드를 수행합니다.
이 때 Back End 와 Front End를 별도의 애플리케이션으로 구현하고 Front End에서 Back End의 파일을 가져올 때 자바스크립트를 사용하는 경우라면 CORS 설정이 반드시 되어 있어야 합니다.
