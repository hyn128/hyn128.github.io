1.Cloud Watch
1)개요
=>리소스 와 애플리케이션을 실시간으로 모니터링하는 서비스
=>이벤트가 발생하면 CloudWatch가 감지를 해서 표현

2)로그
=>애플리케이션의 리소스를 기록
=>CloudWatch에서의 로그는 로그 그룹 단위로 기록
=>여러 서비스에서 발생하는 로그를 기록하며 이를 필요에 따라서 필터링하여 원하는 데이터를 검색할 수 있음
=>로그 기록 만료 시점을 설정할 수 있음
=>로그 그룹 명을 클릭하여 세부 정보를 확인할 수 있음
=>로그 그룹의 현재 저장된 용량을 확인할 수 있고 삭제 및 Amazon S3에 저장할 수 있음
=>Logs Insights를 사용하면 원하는 로그를 쿼리로 호출하여 확인 가능

3)이벤트
=>CloudWatch는 이벤트를 제공
=>규칙을 사용하면 서비스 트리거, Cron Job 같은 형식의 작업이 가능
=>규칙은 이벤트 패턴 또는 일정으로 생성할 수 있음
=>이벤트 패턴은 서비스와 트리거하는 개념으로 특정 서비스를 지정하고 이벤트 유형을 선택한 후 대상 서비스를 지정하여 동작하도록 설정할 수 있음
=>이벤트 패턴은 서비스 단위를 선택할 뿐만 아니라 사용자 지정 이벤트 패턴으로 직접 작성할 수 있음

4)대시보드
=>한 페이지 내에서 원하는 로그를 원하는 형식으로 확인할 수 있음

5)모니터링 종류
=>기본 모니터링
- 무료
- 5분 간격으로 최소한의 데이터를 수집하고 사용자에게 이벤트 발생 여부를 알려줌
- CPU 사용량, 디스크 사용량, 네트워크 I/O 처리량 관련 상황을 체크할 때 사용되는 모니터링 종류
- AWS 리소스 사용 시 ELB 와 RDS를 제외하고 디폴트로 기본 모니터링 종류가 사용됨

=>상세 모니터링
- 유료
- 1분마다 자세한 데이터를 수집
- 대부분의 서비스는 기본 모니터링에서 상세 모니터링으로 변환이 가능하지만 ELB 와 RDS는 상세 모니터링이 기본

6)사용 사례
=>서버 과부화 문제 해결
=>비용 절감 효과: 경보 기능을 활용하면 서버 트래픽이 특정 임계점에 도달했을 때 개발자에게 알림을 주고 성능을 자동으로 낮출 수 있도록 할 수 있음

7)경보
=>상태
- OK: 설정한 임계값에서 타당한 데이터가 들어오는 경우

- ALARM: 임계값을 벗어난 경우

- INSUFFICIENT_DATA: 충분한 데이터가 쌓이지 않은 경우

8)실습
=>EC2 인스턴스 생성

=>용량이 큰 파일을 인스턴스에 전송
- 파일을 다운로드: https://www.jetbrains.com/datagrip/download/

- 파일 전송: scp -i pem파일경로 전송할파일경로 계정@접속할서버:저장될파일경로

=>모니터링 확인: 자동 대시보드에서 EC2 와 EBS를 확인

9)Cloud Watch 경보 생성
=>SNS 서비스에서 생성
- 주제 생성을 클릭해서 정보를 입력
- 주제 안에서 구독을 생성
구독을 할 때 email을 선택하면 이메일이 전송되는데 confirm을 해주면 확인이 됨

=>CloudWatch에서 경보 생성

=>부하 테스트(CPU로 경보를 생성한 경우)
